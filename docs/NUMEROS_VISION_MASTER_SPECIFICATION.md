### 1. Android Native App
- Uses Android Advertising ID (AAID) for advertising use cases under Play policy.
- User-resettable; declared in Google Play Console.
- Tokenized in Identity Vault; never stored raw across application databases.

### 2. iOS Native App
- Uses IDFA **only** when Apple's App Tracking Transparency (ATT) permission is explicitly granted.
- Without ATT authorization, IDFA is returned as all zeros (`00000000-0000-0000-0000-000000000000`).
- No cross-company tracking permitted without ATT.
- Fingerprinting and device property hashing are strictly prohibited.

### 3. PWA
- Uses first-party `nv_installation_id`, `nv_session_id`, and `nv_account_id`.
- Browser/PWA never accesses AAID/IDFA directly.

### 4. Mobile Web
- Uses first-party cookie/storage: `nv_web_id` and optional authenticated account ID.
- First-party web ID is never automatically converted into a cross-company advertising identity.

### Absolute Sensitive Data Exclusion
The following data categories are **BLOCKED FOREVER** from AdTech payloads:
- Raw DOB, birth time, birth place
- Divorce risk / relationship instability predictions
- Health problems, illness, surgery, depression inferences
- Financial distress, debt, insolvency predictions
- Raw user questions, private consultation notes, and custom remedies

Only approved, non-sensitive segments (e.g. `lang_en`, `broad_geo_in`, `product_interest_career_general`) are activated.
